# إعداد مُرشد AI

تُضاف شاشة المحادثة إلى تبويب **مُرشد AI**. يمكن تشغيلها بإحدى طريقتين؛ اختر واحدة فقط:

## الخيار 1: مفتاح API شخصي (BYOK)

1. أنشئ مفتاحًا من لوحة مزودك (مثلاً OpenAI أو Google Gemini أو Groq).
2. افتح التطبيق ← **مُرشد AI** ← الإعدادات.
3. اختر المزود، وأدخل مفتاح API وعنوان Base URL واسم النموذج، ثم اضغط **اختبار الاتصال**.
4. بعد نجاح الاختبار يُحفظ الإعداد على الجهاز في `expo-secure-store`. لا يُضاف المفتاح إلى Git أو ملفات التطبيق أو سجل المحادثة.

هذا الخيار يرسل الطلب مباشرة من جهاز المستخدم إلى المزود؛ لذلك يخرج المفتاح من الجهاز عند إرسال الرسائل إلى المزود المختار. لا تستخدمه على جهاز مشترك، ولا تلصق مفتاحًا يخص فريقًا أو حسابًا مؤسسيًا. يمكن تغيير المزود وعنوان API والنموذج من شاشة الإعدادات، كما يمكن حذف المفتاح المحفوظ. يدعم Gemini مسار Interactions، وتستخدم بقية القوالب واجهة OpenAI-compatible؛ قد تتطلب بعض الخدمات مسارًا أو ترويسة مخصصة غير متوافقة.

## الخيار 2: Backend مركزي (موصى به لتوزيع التطبيق)

لا تضع مفتاح مزود AI داخل التطبيق أو في أي متغير `EXPO_PUBLIC_*`. انشر خدمة `backend/` على Vercel مع ضبط مجلد الجذر `backend`، ثم عيّن في Vercel Environment Variables:

- `AI_PROVIDER=groq` أو `gemini`
- `GROQ_API_KEY` أو `GEMINI_API_KEY` بحسب المزود
- `FIREBASE_PROJECT_ID` — معرّف مشروع Firebase الذي يستخدمه التطبيق
- اختياريًا `GROQ_MODEL` أو `GEMINI_MODEL`

فعّل Anonymous sign-in في Firebase Authentication، ثم أضف متغيرات Firebase العامة الستة إلى بيئة EAS المناسبة: `EXPO_PUBLIC_FIREBASE_API_KEY`، `EXPO_PUBLIC_FIREBASE_AUTH_DOMAIN`، `EXPO_PUBLIC_FIREBASE_PROJECT_ID`، `EXPO_PUBLIC_FIREBASE_STORAGE_BUCKET`، `EXPO_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`، و`EXPO_PUBLIC_FIREBASE_APP_ID`. استخدم قيم تطبيق الويب من إعدادات مشروع Firebase نفسه، واجعلها متاحة في بيئات `production` و`preview` (وفي `development` عند الحاجة). هذه قيم إعداد عميل وليست أسراراً؛ لا تضعها بنوع `Secret` إذا كانت ستُضمّن في JavaScript. عيّن أيضاً `EXPO_PUBLIC_API_BASE_URL` إلى أصل خدمة Vercel (مثال `https://your-project.vercel.app`، من دون `/` أخير)، ثم ابنِ APK جديداً بملف EAS المطابق للبيئة. يستخدم التطبيق Firebase ID token لطلب `/api/ai/chat`، ويظل مفتاح المزود على الخادم. عند ضبط `EXPO_PUBLIC_API_BASE_URL` يتقدم هذا المسار على المفتاح الشخصي المحفوظ.

تفاصيل النشر والبيئة واختبار endpoint موجودة في [دليل Backend](../backend/README.md). لا توجد مفاتيح حقيقية أو بيانات اعتماد في هذا المستودع. نشر Backend على حساب Vercel أو ضبط أسراره يحتاج صلاحية ذلك الحساب.

## المحادثة والخصوصية

- تُحفظ أحدث 12 رسالة محليًا على الجهاز؛ زر سلة المهملات يمسح السجل المحلي.
- لا تُرسل الذاكرة إلى المزود إلا بعد تفعيل زر **استخدام الذاكرة** في شاشة المحادثة. عند تفعيله، يرسل التطبيق حتى خمس ذكريات مقبولة وغير حساسة وذات صلة فقط. لا تُرسل أنواع الذاكرة المصنفة حساسة.
- استخدم فقط ما تسمح به شروط مزودك؛ تحقق من سياسة حفظ الطلبات، ولا ترسل كلمات مرور أو معلومات مالية أو طبية أو تعريفية حساسة.
- الردود مولدة آليًا وقد تخطئ؛ تحقّق من المعلومات المهمة، وخصوصًا الدينية أو الصحية أو القانونية.
- BYOK يعني أن المفتاح على الجهاز ويُستخدم للاتصال المباشر بالمزود. أما Backend المركزي فيحتاج تهيئة Firebase وVercel منفصلة قبل أن يعمل الإصدار الموزع.

## الاختبارات

من جذر المستودع:

```bash
npm run ai:test
npm run check
npm run backend:test
npx expo export --platform android --output-dir /tmp/murshid-ai-export
```

تستخدم الاختبارات مزودات وهمية ولا تتطلب مفتاح API حقيقيًا. اختبار الاتصال الفعلي متاح من إعدادات التبويب على جهاز أو محاكي بعد إدخال مفتاح يملكه المستخدم.
